# SHOP-231: Ветка release/1.3.0 не собирается и не стартует

| | |
|---|---|
| Тип | Bug |
| Приоритет | **Blocker** |
| Компоненты | build, payment, pricing, db |
| Автор | Андрей К. (Tech Lead) |
| Связано | SHOP-212 (СБП), SHOP-215 (крипто), SHOP-205, [ADR-0002](../adr/0002-payment-methods.md) |

## Описание

В пятницу смержили в `release/1.3.0` две фичи, которые параллельно делали Вася (СБП) и Петя (крипто).
Каждая ветка по отдельности проходила сборку. После мержа:

```
./mvnw clean package
...
[ERROR] COMPILATION ERROR
```

Вася на скорую руку поправил компиляцию у себя локально (в репозиторий не пушил), и тогда упал
старт приложения. После следующей правки упало в другом месте. Он сдался на третьей ошибке.

У Пети локально «всё стартует». Правда, у него в корне лежит свой `application-local.yml`,
и запускает он с профилем `local`.

## Шаги воспроизведения

1. Чистый клон репозитория.
2. `cp .env.example .env && docker compose up -d`
3. `./mvnw clean spring-boot:run`

## Ожидаемый результат

Сервис собирается и стартует на пустой БД без дополнительных локальных файлов. `/actuator/health` → `UP`.

## Фактический результат

Ошибка компиляции, а после её исправления — серия ошибок старта.

## Комментарии

**Андрей К.:** Чинить по одной ошибке до первого зелёного запуска нельзя. Каждая ошибка старта
указывает на проблему в дизайне или процессе. Я хочу видеть исправленную причину, а не заглушённый
симптом. Варианты вроде `@Primary`, `spring.main.allow-circular-references=true`,
`ddl-auto: update` или `@Lazy`, «чтобы завелось», ревью не пройдут.

**Андрей К.:** Напоминаю, что в ADR-0002 мы договорились, как подключать способы оплаты.
И посмотрите в ARCHITECTURE.md, кто от кого может зависеть.

**Пётр С.:** У меня ключ для криптопроцессинга лежит в локальном конфиге, его же нельзя коммитить?

## Критерии приёмки

- [ ] `./mvnw clean package -DskipTests` проходит.
- [ ] Приложение стартует на пустой БД из `docker compose` без локальных конфигов.
- [ ] Секреты не закоммичены; при этом понятно, какие переменные окружения нужно задать
      (`.env.example`, README). Для dev-стенда есть безопасные значения по умолчанию.
- [ ] Добавление нового способа оплаты не требует правок в `CheckoutService`, `PaymentService` и других
      существующих классах. Проверь это мысленным экспериментом с «Долями».
- [ ] Граф зависимостей модулей соответствует ARCHITECTURE.md.
- [ ] Номера миграций Flyway не конфликтуют. Подумай, почему конфликт не поймали до мержа и как
      предотвратить такое в будущем (запиши в описание PR).
