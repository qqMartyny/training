# SHOP-251: Покупатели получают письма о заказах, которых не существует

| | |
|---|---|
| Тип | Bug |
| Приоритет | Major |
| Компоненты | notification, order |
| Автор | Команда Notification Service |
| Связано | [ADR-0003](../adr/0003-order-events.md), [SPECIFICATION.md §7.2](../SPECIFICATION.md) |

## Описание

Нам приходят события `NEW` по заказам, которых потом нет ни в API Order Service, ни у службы доставки.
Покупатели получают письмо «Ваш заказ №… оформлен», а в личном кабинете заказа нет. Обычно это
совпадает по времени с `409 OUT_OF_STOCK` у того же покупателя.

## Комментарии

**Андрей К.:** Как и SHOP-250, это проблема границ транзакций, только видна снаружи. Чините после SHOP-250,
иначе не воспроизведёте. Решение есть в ADR-0003. Заодно уберите Kafka из доменного модуля `order`.

## Критерии приёмки

- [ ] Событие уходит в Kafka только после коммита изменения.
- [ ] `order` не зависит от Kafka и модуля `notification`.
- [ ] Тест: checkout с `OUT_OF_STOCK` → в топике нет событий по этому покупателю.
