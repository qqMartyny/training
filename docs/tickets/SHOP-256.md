# SHOP-256: Ревизия автотестов: зелёные тесты, которые ничего не проверяют

| | |
|---|---|
| Тип | Tech debt |
| Приоритет | Major |
| Компоненты | tests (все модули) |
| Автор | Андрей К. (Tech Lead) |

## Описание

Почти по каждому багу из этого спринта в комментариях есть «а тест зелёный». Так быть не должно.
Нужна ревизия всех тестов в проекте.

Признаки, на которые стоит смотреть:

- тест проходит, если удалить или сломать тестируемый код;
- тест проверяет мок вместо реального кода;
- в тесте нет ни одной проверки, которая может упасть;
- тест не запускается;
- тест проходит благодаря особенностям окружения теста, которых нет в проде;
- тестовые данные не похожи на продовые;
- тест называется «конкурентный», «кэш», «идемпотентность», но проверяет что-то другое.

## Критерии приёмки

- [ ] В PR приложен список найденных проблемных тестов (класс, метод, что с ним не так) и что сделано
      с каждым: исправлен, переписан или удалён с обоснованием.
- [ ] Для каждого исправленного теста проверено, что он **падает**, если сломать код
      (ручная мутация: поменяй `<` на `<=`, убери строку и т. п.).
- [ ] *Бонус:* подключи PIT (mutation testing) хотя бы для модулей `pricing` и `order` и приложи отчёт.
