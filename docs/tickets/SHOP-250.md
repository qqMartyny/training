# SHOP-250: Товар не возвращается на склад

| | |
|---|---|
| Тип | Bug |
| Приоритет | **Critical** |
| Компоненты | checkout, inventory, order |
| Автор | Склад заказчика (через Ольгу Н.) |
| Связано | [ARCHITECTURE.md §3](../ARCHITECTURE.md), [SPECIFICATION.md §5.3, §6.3](../SPECIFICATION.md) |

## Описание

По данным сервиса остатки стабильно меньше реальных: за неделю «пропало» около 40 единиц разных товаров.
Сверка показала три сценария:

1. Банк отказал в оплате (`PAYMENT_FAILED`): резерв не снимается.
2. Покупатель отменил заказ (`CANCELLED`): резерв не снимается.
3. Покупатель положил в корзину мышь и 6 мониторов (а на складе 5) → `409 OUT_OF_STOCK`, это правильно.
   Но остаток мышей уменьшился на 1, а в базе появился заказ в статусе `NEW`, которого покупатель
   не видел.

## Комментарии

**Василий П.:** Странно, там же стоит `@Transactional` на создании заказа и резерве.

## Критерии приёмки

- [ ] Все три сценария исправлены и покрыты интеграционными тестами, которые проверяют остатки.
- [ ] В PR объяснено, почему `@Transactional` не сработал.
- [ ] Транзакция БД не держится открытой во время запроса к платёжному провайдеру.
