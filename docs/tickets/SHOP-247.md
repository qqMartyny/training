# SHOP-247: Покупатель отменил уже доставленный заказ

| | |
|---|---|
| Тип | Bug |
| Приоритет | **Critical** |
| Компоненты | order |
| Автор | Светлана Р. (поддержка) |
| Связано | [SPECIFICATION.md §5](../SPECIFICATION.md) |

## Описание

Покупатель получил монитор, через неделю нажал «Отменить заказ» в личном кабинете. Заказ перешёл
в `CANCELLED`, бухгалтерия автоматически оформила возврат 32 990 ₽. Монитор остался у покупателя.

Ещё обращение: заказ, который не удалось оплатить (`PAYMENT_FAILED`), сервис доставки перевёл в `SHIPPED`
(у них баг на их стороне). Мы это приняли.

## Комментарии

**Мария Л. (QA):** Тест `OrderStatusTest.deliveredOrderCannotBeCancelled` есть и зелёный.

**Андрей К.:** Правила переходов должны жить в одном месте, в доменной модели. Тогда их не обойдёт
ни контроллер, ни callback, ни сервис доставки. Посмотри паттерн State. Или хотя бы таблицу переходов
внутри enum. Выбор обоснуй в PR.

## Критерии приёмки

- [ ] Все переходы соответствуют диаграмме из §5, недопустимые возвращают `409 ILLEGAL_STATUS_TRANSITION`.
- [ ] Изменить статус в обход правил невозможно (у `Order` нет публичного «сеттера» статуса).
- [ ] Параметризованный тест покрывает **все** пары статусов (разрешённые и запрещённые).
