# SHOP-248: Повторный callback от СБП откатывает статус заказа

| | |
|---|---|
| Тип | Bug |
| Приоритет | Major |
| Компоненты | payment, order |
| Автор | Команда Delivery Service |
| Связано | [SPECIFICATION.md §4.4](../SPECIFICATION.md), [openapi.yaml](../api/openapi.yaml) `/payments/callback` |

## Описание

Мы получили событие `SHIPPED` по заказу, создали отправление, передали курьеру. Через 40 минут
пришло событие `PAID` по тому же заказу. Наш сервис решил, что заказ ещё не отправлен,
и создал второе отправление.

Провайдер СБП подтвердил, что повторно отправлял callback `SUCCEEDED`: у них был таймаут
при первой доставке. Это штатное поведение, описанное в их документации (at-least-once).

## Критерии приёмки

- [ ] Повторный callback по уже завершённому платежу ничего не меняет и возвращает `200`.
- [ ] Callback со статусом `PENDING` (бывает у крипто-провайдера) не ломает заказ.
- [ ] Тест: callback дважды → статус заказа и количество событий в Kafka как после одного callback.
- [ ] Подумай, что будет, если два одинаковых callback придут **одновременно**. Опиши в PR.
