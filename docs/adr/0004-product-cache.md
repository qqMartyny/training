# ADR-0004: Кэширование карточек товаров в Redis

- **Статус:** Accepted
- **Дата:** 2026-07-20
- **Автор:** Пётр С.

## Контекст

При каждом пересчёте корзины загружаются карточки всех товаров в ней. На распродаже это
десятки тысяч одинаковых запросов в минуту (SHOP-190).

## Решение

- Cache-aside через Spring Cache (`@Cacheable`), провайдер — Redis, кэш `products`, TTL 10 минут.
- В кэше хранится неизменяемый DTO (`record`), а не JPA-сущность. Сущность привязана к persistence context,
  может содержать lazy-прокси, и её структура меняется вместе со схемой БД.
- Любое изменение товара (цена, активность) инвалидирует запись кэша для этого товара.
  TTL — страховка, а не механизм обновления.

## Последствия

- Если Redis недоступен, запросы к товарам падают. В бэклоге есть задача на `CacheErrorHandler`, чтобы деградировать до чтения из БД.
- Изменение формата DTO требует сброса кэша при деплое (или версионирования ключей).
